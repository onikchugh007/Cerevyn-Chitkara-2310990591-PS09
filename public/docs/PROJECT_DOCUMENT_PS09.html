02 Problem Statement

2.1. What PS09 Asks to Build

Problem Statement 09 (PS09) mandates engineering an adaptive, full-stack memory matching web application that begins with a balanced 4×4 grid (8 pairs) and incorporates deterministic board generation, input safety invariants, telemetry logging, and automated cognitive difficulty calibration without relying on paid third-party APIs.

2.2. Shortcomings of Traditional Memory Games

  • Non-Deterministic Randomization: Conventional games rely on Math.random(), making seed-based replays and reproducible test assertions impossible.
  • Rapid-Click Race Conditions: Without synchronous state machine guards, players can click 3 or 4 cards simultaneously during mismatch resolution, breaking game rules.
  • Ghost Flips on Restart: Poor timer cleanup leaves unresolved setTimeout() handles active; restarting a game causes delayed callbacks to flip cards in the next session.
  • Opaque Progression: Traditional games feature static difficulty without assessing working memory capacity, latency, or cognitive fatigue.
  • Timer Distortion: Timers keep running when the user switches tabs, skewing cognitive evaluation metrics.

03 Project Objectives

  1. Adaptive Difficulty: Dynamically scale matrix complexity across Novice (3×4, 6 pairs), Standard (4×4, 8 pairs), and Advanced (6×6, 18 pairs) based on player recall efficiency.
  2. Deterministic Seed-Based Permutation: Implement a Mulberry32 PRNG and Fisher-Yates shuffle ensuring any string seed (e.g. DOGE-01) reliably regenerates identical boards.
  3. Precision Move & Time Tracking: Increment move counts strictly upon completing a pair attempt, while using the Page Visibility API to pause time during tab blur.
  4. Explainable Cognitive Efficiency: Compute player cognitive efficiency: Efficiency (%) = (Theoretical Min Moves / Actual Moves) × 100 with transparent clinical reasoning.
  5. Click & Restart Safety: Enforce 3rd-card click lockout (isResolvingPair = true), duplicate click immunity, and synchronous timer aborts on restart.

05 System Architecture

The system is organized into decoupled client and server tiers communicating via REST over HTTP:

  • Frontend Client: Handles 3D card flips, locks inputs during mismatch comparisons, and produces synthetic sound waves.
  • Node.js Express API: Serves deterministic boards, records completed sessions, and outputs explainable progression recommendations.
  • Seed Engine: Employs FNV-1a hashing and Mulberry32 PRNG to deliver statistically uniform card permutations.
  • Adaptive Engine: Evaluates moves and elapsed seconds against cognitive thresholds.
  • Session Store: Thread-safe ring buffer persisting telemetry asynchronously to local JSON storage.

07 Adaptive Progression Algorithm

Player working-memory performance is evaluated using the Cognitive Efficiency formula:

Cognitive Efficiency (%) = (Theoretical Minimum Moves / Actual Moves) × 100

(Theoretical minimum moves = Number of Pairs in the active board)

Difficulty Tiers

  • Novice (NPC Tutorial): 3 × 4 Grid → 6 pairs (Min moves = 6)
  • Standard (Dank Matrix): 4 × 4 Grid → 8 pairs (Min moves = 8) — Default mode
  • Advanced (Gigachad Galaxy): 6 × 6 Grid → 18 pairs (Min moves = 18)

Calibration Decision Matrix

Current Mode Trigger Condition Action Next Mode Cognitive Rationale
Standard (4×4) Moves ≤ 14 & Time ≤ 35s PROMOTE Gigachad Galaxy (6×6, 18 pairs) Rapid visual search and high recall; capacity exceeds standard load.
Standard (4×4) Moves ≥ 22 & Time ≥ 65s DEMOTE NPC Tutorial (3×4, 6 pairs) Working-memory overload or fatigue; stepping down to re-establish baseline.
Standard (4×4) 15–21 Moves & 36–64s MAINTAIN Standard (4×4, 8 pairs) Steady baseline performance; retaining current level.
Novice (3×4) Moves ≤ 10 & Time ≤ 25s PROMOTE Standard (4×4, 8 pairs) Tutorial cleared; promoting to standard 8-pair matrix.

08 REST API Documentation

8.1. GET /api/health

Liveness and container health probe returning uptime and system timestamp.

// Response (200 OK)
{ "status": "healthy", "uptime": 142.5, "environment": "production" }

8.2. GET /api/game/new

Generates a deterministic board matching the requested seed and difficulty parameters.

// Sample Request: GET /api/game/new?seed=DOGE-01&difficulty=standard
// Response (200 OK)
{
  "seed": "DOGE-01",
  "difficulty": "standard",
  "rows": 4, "cols": 4, "totalCards": 16, "totalPairs": 8,
  "cards": [
    { "cardId": "c_0", "pairId": "p_doge", "name": "Doge", "imagePath": "/images/memes/doge.jpg", "color": "#f59e0b" },
    { "cardId": "c_1", "pairId": "p_drake", "name": "Drake Hotline Bling", "imagePath": "/images/memes/drake.jpg", "color": "#00f2fe" }
  ]
}

8.3. POST /api/game/session

Submits completed round metrics and receives explainable difficulty adaptation rules.

// Request Payload: { "seed": "DOGE-01", "difficulty": "standard", "moves": 12, "pairs": 8, "elapsedSeconds": 28.5 }
// Response (201 Created)
{
  "success": true,
  "adaptation": {
    "previousDifficulty": "standard", "nextDifficulty": "advanced",
    "action": "PROMOTE", "ruleId": "RULE_PROMOTION_OVERCLOCK",
    "reasonSummary": "🏆 GIGACHAD ASCENSION (200 IQ)"
  },
  "metrics": { "theoreticalMinMoves": 8, "actualMoves": 12, "pairs": 8, "elapsedSeconds": 28.5, "efficiency": 67 }
}

8.4. GET /api/game/analytics

Returns aggregate telemetry (total rounds, average moves, average latency) and recent session history.

8.5. GET /api/game/rules

Returns the documented adaptation threshold schema and grid dimensions for client verification.

10 Azure Cloud Deployment Plan

  • Azure App Service / ACA: Hosted on Linux Node 20 LTS with automated continuous deployment from the GitHub repository. Serverless autoscaling supports 0 to 5 container replicas.
  • Deployment Process: GitHub Actions workflow authenticates against Azure via OpenID Connect (OIDC) federated credentials, eliminating hardcoded keys.
  • Environment Variables: Credential-free default configuration via .env.example with production runtime overrides: PORT=3000, NODE_ENV=production.
  • Monitoring: Continuous liveness health checks against /api/health with automated container restarts upon unresponsiveness.
  • Cost Considerations: Runs 100% free within the Azure for Students $100 annual credit grant or the Free F1 tier.
